1. Procedure: Generate PWM Signals and Capture via Oscilloscope

For this lab, the procedure focuses on the first general test case where the oscilloscope is used to record the PWM signals generated via the Launchpad. Figure 1 shows the PWM signal when the servo motor is set to move to 0 degrees. What is shown is one period of a continuous PWM signal that has an approximate amplitude of 3.3 V and and has a pulse width of 1.85 ms. The servo motor burned during this process, so it was not possible to test the servo motor. Any figures that depict the waveforms from the oscilloscope were taken without using the servo motor.

There is a typical process for using motors which was practiced during this lab. It is desired to have the motor rotate to a specific position which would be 0 degrees. To do this, the Launchpad generates a PWM signal that is fed into the servo motor. The basis of a PWM signal is that the pulse width of the signal that is fed into the servo motor can be modified to any value between 0-99%. This allows the Launchpad to choose which direction the servo motor turns and how far it should turn. If a 50% duty cycle is the threshold to determine if the servo motor should move clockwise or counterclockwise, a 40% duty cycle would tell the motor to turn in the counterclockwise direction for a small distance. In comparison, a 90% duty cycle would tell the motor to turn in the clockwise direction and turn a greater distance compared to the 40% duty cycle.

Next, Figure 2 also shows the PWM signal sent to the servo motor. However, the waveform has been modified to display a pulse width of 576 us as requested in the procedure of the lab. The servo motor is capable of accepting a pulse width between 553 us to 2425 us, so the current pulse width is acceptable as it is slightly above the minimum pulse width that was specified. It is important to ensure that the inputs to any system are within acceptable ranges to ensure optimal performance and to prevent damage to those systems.

Compared to the waveform displayed in Figure 1, the waveform depicted in Figure 3 is larger. Figure 1 was meant to demonstrate the counterclockwise movement of the servo motor to 0 degrees which requires the duty cycle to be less than 50%. To demonstrate the movement of the servo motor in the clockwise direction, the duty cycle must at least be greater than 50% which explains the difference in size of the waveform in Figure 3 compared to Figure 1.

COnsidering that the maximum pulse width of the servo motor is approximately 2400 us, the duty cycle shown here is most likely close to a 100%. This means that in Figures 1-4, the minimum and maximum duty cycles of the servo motor was tested to demonstrate how the duty cycle can affect the movement of the servo motor.

2. Tasks: Configure the T1 RSLK MAX to Drive and Avoid Obstacle Collison 

With the completion of the procedure, the second half of the lab is dedicated to configuring the code in the Launchpad to allow the TI-RSLK MAX to drive itself and prevent damage from collison with obstacles. Initially, the Launchpad needs to be configured to accept input from the bumpers attached to the TI-RSLK MAX. This will ensure that the robot will be able to detect when it collides with obstacles, stop moving forward, reverse itself to stop colliding with the obstacle, and rotate into another direction away from the obstacle. To verify that the bumpers have been configured correctly, the terminal and oscilloscope can be used. The outputs from the terminal can be used to verify that the Launchpad is able to detect when the bumpers have been pressed when the robot has collided with an object. The output from the oscilloscope is used to verify the bumper generates a signal when triggered. Additionally, it is used to observe the bouncing effect of the bumpers when pressed. 

Next, the Launchpad is configured to initialize Timer A0 so the proper PWM signals can be used to move the gear motors on the TI-RSLK MAX. Then, the Launchpad is configured to output PWM signals to the gear motors from Timer A0. Several functions are generated to specify how the Launchpad should send PWM signals to the gear motors, so the robot will be capable of moving forward, backward, left, right, or stopping. Afterwards, a few additional functions are created in the Launchpad to provide instructions on how to stop the robot when it collides with an object and how to correct its position after a collison. Lastly, the final step is to demonstrate to the professor that the Launchpad has been configured correctly by allowing the robot to move around in the classroom. 

For the bumper, the terminal output is shown in Figure 5 and the oscilloscope output is shown in Figure 6. In Figure 5, each bumper is pressed to confirm that all of the bumpers have been configured correctly. Since there are 6 bumpers, each bumper is a assigned a bit from 0 to 5. Each bumper was pressed one at a time, so Figure 5 shows that there is only a single bit active at a time which is the bumper that was pressed. There are multiple instances of a bumper being pressed due to the bouncing effect which is expected. The bouncing effect is easier to see in Figure 6 where the effect causes the signal from the bumper to constantly change in value until eventually the input from the bumper has settled. After that, the interrupt signal to notify the Launchpad that the bumper has been pressed is generated as shown in the other waveform depicted in Figure 6. This will allow the Launchpad to determine that the robot has collided with an object and cease its current action to perform a different action to ideally protect itself from damage.

Other than Figures 5-6, there are no other images to present in the report as the concepts in the tasks are complex and can only be demonstrated by showing that the robot moves during the lab time. Instead, the final discussion will about the mechanics of using the motors to move the robot. Compared to the servo motor, the gear motors are more complex in that they have additional inputs. Other than a PWM signal input, the gear motors have a direction input that indicates what direction it should rotate in and an enable input that indicates if the motor should be active. To move the robot forward, the Launchpad will tell both gear motors to turn forward and provide a duty cycle between 0-99% to indicate the speed at which the gear motors should turn. To move the robot left or right, the Launchpad will tell one gear to move forward and the other gear to move backward. Lastly to stop the robot, the Launchpad can disable the gear motors to stop movement.
